# Стандарт кодування проєкту ClinicReception

Версія 1.0 · листопад 2026

## 1. Загальні положення

Стандарт діє для всього коду репозиторію ClinicReception (варіант № 4: запис
пацієнтів на прийом до лікаря): бібліотеки `ClinicReception.Core`,
консольного застосунку `ClinicReception.App` і тестів, що з'являться пізніше.

- **G1.** Кожен пункт стандарту має код (G, N, F, C, S, K). У коментарях огляду
  коду посилаємося на код пункту, наприклад «порушено N5».
- **G2.** Пункти, позначені 🔧, перевіряються автоматично (розділ 7). Решту
  перевіряє рецензент за чеклістом.
- **G3.** Проєкт має збиратися командою `dotnet build` з 0 попереджень і 0 помилок.
  Попередження не накопичуються: або виправляємо код, або вимикаємо правило
  в `.editorconfig` з коментарем-обґрунтуванням.

## 2. Іменування

Усі ідентифікатори англійською мовою, без транслітерації (`Patient`, а не
`Pacient`) і без скорочень, крім загальноприйнятих (`Id`, `Url`).

| Код | Сутність | Конвенція | Приклад | Антиприклад |
| --- | --- | --- | --- | --- |
| N1 | Клас, запис | PascalCase, іменник | `VisitItem` | `visititem`, `VisitItemClass` |
| N2 | Інтерфейс 🔧 | `I` + PascalCase | `IAppointmentRepository` | `AppointmentRepository` |
| N3 | Метод | PascalCase, дієслово | `AddItem`, `TotalMinutes` | `item`, `calc` |
| N4 | Властивість | PascalCase, іменник | `StartTime` | `GetStartTime` |
| N5 | Приватне поле 🔧 | `_` + camelCase | `_items` | `m_Items`, `items` |
| N6 | Локальна змінна, параметр | camelCase | `endTime` | `et`, `EndTime` |
| N7 | Константа | PascalCase | `MaxSlotsPerDay` | `MAX_SLOTS` |
| N8 | Перелічення | PascalCase, однина | `VisitStatus` | `VisitStatuses` |
| N9 | Булеве значення | префікс `Is`/`Has`/`Can` | `HasInsurance` | `Insurance` |

- **N10.** Величина з одиницею виміру містить одиницю в імені:
  `DurationMinutes`, `SlotMinutes`. Ім'я `Duration` типу `int` заборонене —
  незрозуміло, хвилини це чи секунди.
- **N11.** Межі часового інтервалу називаються парою `Start…`/`End…`
  (`StartTime`, `EndTime`). Інтервал напіввідкритий: `End` не входить до
  прийому, тож прийом 09:30–10:05 і наступний з 10:05 не перетинаються.
- **N12.** Імена методів-запитів не мають побічних ефектів і не починаються з
  `Set`/`Update`; `Total()` лише рахує, але нічого не змінює.

## 3. Форматування

- **F1.** 🔧 Відступ — 4 пробіли; табуляція заборонена. У `.csproj`, `.props`,
  `.json`, `.yml` — 2 пробіли.
- **F2.** Довжина рядка — не більше ніж 100 символів.
- **F3.** 🔧 Фігурні дужки — стиль Allman (на новому рядку) і обов'язкові навіть
  для однієї інструкції в тілі `if`, `foreach`.
- **F4.** 🔧 Між членами класу — рівно один порожній рядок; два порожні рядки
  поспіль заборонені.
- **F5.** 🔧 Директиви `using` — на початку файлу, поза простором імен, системні
  першими; невживані видаляються.
- **F6.** 🔧 Простір імен — файлового рівня (`namespace ClinicReception.Core.Domain;`).
- **F7.** 🔧 Порядок членів класу: поля → конструктори → властивості → методи.
- **F8.** Один публічний тип — один файл; ім'я файлу збігається з іменем типу.
- **F9.** 🔧 Без пробілів у кінці рядка; файл закінчується порожнім рядком.
- **F10.** Багаторядковий ініціалізатор об'єкта — одна властивість на рядок.

## 4. Коментарі та документація

- **C1.** Коментар пояснює **чому**, а не **що**. Коментар, який переказує код,
  видаляється під час огляду.

```csharp
// погано: коментар переказує код
// додаємо тривалість послуги до хвилин
minutes += item.Quantity * item.DurationMinutes;

// добре: коментар пояснює причину рішення
// кінець інтервалу не входить до прийому, тож суміжні слоти не перетинаються
bool overlaps = start < other.EndTime && other.StartTime < end;
```

- **C2.** Кожен публічний тип і метод бібліотеки `Core` має XML-коментар
  `<summary>`; метод із параметрами — `<param>`, метод, що повертає значення, —
  `<returns>`. Обов'язковість для властивостей — з ЛР № 4.
- **C3.** Мова коментарів і повідомлень користувачу — українська; мова
  ідентифікаторів — англійська.
- **C4.** Закоментований код у репозиторії заборонений: історію зберігає Git.
- **C5.** `TODO` дозволено лише з номером задачі або роботи: `// TODO(ЛР5): …`.

## 5. Структура проєкту

- **S1.** `ClinicReception.Core` — уся логіка предметної області; не звертається
  до `Console` і не читає файли напряму.
- **S2.** `ClinicReception.App` — лише введення й виведення; посилається на `Core`,
  а не навпаки.
- **S3.** Сутності предметної області лежать у теці `Domain`, простір імен
  відповідає теці.
- **S4.** Гроші — лише `decimal` (суфікс `m` у літералах: `650.00m`); дата
  прийому — `DateOnly`, час початку — `TimeOnly`, момент створення запису —
  `DateTimeOffset`. Тип `DateTime` і `double` для грошей заборонені.
- **S5.** Стан запису — лише перелічення `VisitStatus`, а не рядок чи число.
- **S6.** Числа, що мають зміст у предметній області (тривалість слота,
  межа робочого дня), — іменовані константи, а не «магічні» літерали.

## 6. Правила комітів

- **K1.** Повідомлення за Conventional Commits: `тип: коротка суть` українською,
  у минулому часі доконаного виду («додано», «виправлено»).

| Тип | Коли | Приклад |
| --- | --- | --- |
| `feat` | нова можливість | `feat: додано розрахунок тривалості прийому` |
| `fix` | виправлення дефекту | `fix: виправлено перетин суміжних слотів` |
| `docs` | документація | `docs: додано стандарт кодування і README` |
| `chore` | інфраструктура | `chore: увімкнено аналізатори` |
| `style` | лише форматування | `style: приведено відступи до 4 пробілів` |
| `refactor` | зміна будови без зміни поведінки | `refactor: виділено метод TotalMinutes` |
| `test` | тести | `test: додано тести розрахунку суми` |

- **K2.** Один коміт — одна завершена зміна; після кожного коміту рішення
  збирається без попереджень.
- **K3.** Теки `bin`, `obj` і локальні файли `*.user` до репозиторію не потрапляють
  (`.gitignore`).
- **K4.** Кожна лабораторна робота завершується тегом `labN`.
