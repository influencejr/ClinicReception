# ClinicReception

Навчальний проєкт з дисципліни «Конструювання програмного забезпечення».
Варіант № 4: запис пацієнтів на прийом до лікаря.

Бібліотека `ClinicReception.Core` містить доменні типи реєстратури клініки
(пацієнт, лікар, запис на прийом, послуга, стани запису) і клас `Visit`,
успадкований модуль розрахунку вартості візиту, приведений до стандарту
кодування в ЛР № 2. Консольний застосунок поки демонструє роботу класу `Visit`:
рахує вартість візиту без страхової знижки та з нею, змінює стан візиту й
друкує звіт про надані послуги.

## Склад рішення

- `src/ClinicReception.Core` — логіка предметної області (бібліотека класів).
- `src/ClinicReception.App` — консольний застосунок (введення й виведення).
- `docs/lab02` — еталонний вивід застосунку до і після приведення коду
  до стандарту.

## Вимоги

.NET SDK 8.0 або новіший, Git.

## Складання та запуск

```bash
git clone https://github.com/influencejr/ClinicReception.git
cd ClinicReception
dotnet build
dotnet run --project src/ClinicReception.App
```

## Стандарт кодування

Правила описано у файлі [CODING_STANDARD.md](CODING_STANDARD.md) і закріплено
в `.editorconfig`, `Directory.Build.props` та аналізаторах Roslyn і StyleCop.
Складання налаштовано в режимі «попередження як помилки». Перевірка:

```bash
dotnet format --verify-no-changes
dotnet build
```

## Виконані роботи

| Робота | Тема | Мітка |
|---|---|---|
| ЛР № 1 | Середовище конструювання та стандарт кодування проєкту | `lab1` |
| ЛР № 2 | Приведення коду до стандарту: іменування, форматування, коментарі | `lab2` |

## Відомі обмеження

Дані задаються в коді, читання з файлу ще не реалізоване. Клас `Visit`
зберігає стан числом і не перевіряє вхідні дані; ці борги записано у звіті
ЛР № 2 і заплановано на наступні роботи.
