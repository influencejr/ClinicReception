# ClinicReception

![CI](https://github.com/influencejr/ClinicReception/actions/workflows/ci.yml/badge.svg)

Навчальний проєкт з дисципліни «Конструювання програмного забезпечення».
Варіант № 4: запис пацієнтів на прийом до лікаря.

Бібліотека `ClinicReception.Core` рахує вартість візиту до клініки: сума послуг
зі знижкою за курс процедур, знижки постійному пацієнтові, за обсягом, за
промокодом і за прийом у неділю, реєстраційний збір для невеликого візиту та
новий стан візиту. Звіт формується окремою чистою функцією.

Запис на прийом (`Appointment`) — агрегат зі станами й перевіреними
інваріантами. `AppointmentService` записує пацієнта, рахує вартість за
підставленою політикою ціноутворення й сповіщає пацієнта; сховище, політика та
сповіщувач передаються в конструктор як інтерфейси. Консольний застосунок
складає всі об'єкти в `Program.cs`, рахує демонстраційні візит і запис,
приймає послуги з консолі та друкує результати.

Помилки оброблено за класами (таблиця в `docs/errors.md`). Введення з консолі
розбирає `VisitItemParser` у застосунку й повертає `Result`, тож на помилку
вводу програма пояснює, що не так, і питає ще раз. Порушення правил запису ядро
повідомляє винятком `DomainRuleException` з ідентифікатором правила. Сервіс
веде журнал через `ILogger` (рівні Debug, Information, Warning, Error, область
з номером запису), журнал виводиться в stderr. Операції дописуються у файл
`audit.log`, CSV-звіт зберігається в `reports/appointments.csv`.

## Склад рішення

- `src/ClinicReception.Core` — логіка предметної області (бібліотека класів):
  `Domain` — сутності й стани, `Abstractions` — інтерфейси сховища, політики
  цін і сповіщень, `Services` — прикладний сервіс записів, `Pricing`,
  `Storage`, `Notifications` — їхні реалізації та журнал аудиту, `Errors` —
  `DomainRuleException` і `Result`, `Billing` — розрахунок вартості візиту з
  ЛР № 3, `Reporting` — звіти.
- `src/ClinicReception.App` — консольний застосунок: `Input` — розбір введення
  (барикада), верхній обробник винятків і налаштування журналу в `Program.cs`.
- `src/Legacy` — успадкований модуль ЛР № 6 (`ClinicReception.Legacy`),
  відрефакторений за каталогом; аналізатори для нього поки вимкнено.
- `tests/ClinicReception.Tests` — модульні тести xUnit.
- `tests/Legacy.Tests` — характеризаційні тести успадкованого модуля.
- `docs/model.md` — класова модель: сутності, інваріанти, стани запису.
- `docs/errors.md` — класифікація помилок і стратегії їх обробки.
- `docs/smells.md`, `docs/metrics.md`, `docs/tech-debt.md` — реєстр дефектів
  успадкованого модуля, метрики до й після рефакторингу, реєстр технічного боргу.
- `docs/lab02`, `docs/lab03`, `docs/lab04` — артефакти лабораторних робіт
  (еталонний вивід, метрики, аудит SOLID).

## Вимоги

.NET SDK 8.0 або новіший, Git.

## Складання та запуск

```bash
git clone https://github.com/influencejr/ClinicReception.git
cd ClinicReception
dotnet build
dotnet run --project src/ClinicReception.App
```

Застосунок просить ввести послуги до запису одним рядком: код, кількість,
ціна, хвилини, наприклад `LAB-02 1 180,50 10`. Порожній рядок завершує
введення. Щоб побачити лише журнал, без діалогу:

```bash
dotnet run --project src/ClinicReception.App 2>&1 >/dev/null
```

Коди виходу: 0 — успіх, 1 — порушено правило предметної області, 2 —
непередбачений збій, 3 — файл `audit.log` зайнятий іншою копією програми.

## Тести

```bash
dotnet test
```

Покриття рахує coverlet, HTML-звіт будує ReportGenerator
(`dotnet tool install -g dotnet-reportgenerator-globaltool`):

```bash
dotnet test --collect:"XPlat Code Coverage"
reportgenerator -reports:"tests/**/coverage.cobertura.xml" -targetdir:coverage
```

Каталоги `TestResults/` і `coverage/` до репозиторію не потрапляють. Таблиці
тестових даних і непокритих гілок — у [docs/testing.md](docs/testing.md).
Ручні тестові дублери (фейк сховища, стаби політики цін і сповіщувача) лежать
у `tests/ClinicReception.Tests/Doubles`.

## Безперервна інтеграція

Конвеєр `.github/workflows/ci.yml` запускається на кожен push у `main` і
`feature/**` та на кожен pull request у `main`. Складання на сервері
закріплено на .NET SDK 8. Зміна потрапляє в `main`, лише коли пройдено всі
критерії якості:

| Крок | Команда | Що ламає збірку |
|---|---|---|
| Формат | `dotnet format --verify-no-changes` | зайвий пробіл, відступ, порядок using |
| Складання | `dotnet build -c Release` | будь-яке попередження CS, CA, SA, IDE або NU (вразливий пакет) |
| Тести | `dotnet test -c Release` | хоча б один червоний тест |
| Покриття | coverlet, `/p:Threshold=60` | покриття рядків будь-якого модуля нижче за 60 % |

Те саме локально:

```bash
dotnet format --verify-no-changes
dotnet build -c Release
dotnet test -c Release /p:CollectCoverage=true /p:Threshold=60 /p:ThresholdType=line
```

Спільні властивості складання (версія, мова, аналізатори, аудит пакетів)
задано в `Directory.Build.props`. Застосунок виводить версію першим рядком.

Правила описано у файлі [CODING_STANDARD.md](CODING_STANDARD.md) і закріплено

## Відомі обмеження

Пацієнти й записи задаються в коді, з консолі вводяться лише послуги, читання
з файлу ще не реалізоване. Сховище записів працює лише в пам'яті. Сповіщувач
`OfflineNotifier` у застосунку навмисно імітує недоступний поштовий сервер,
щоб показати обробку збою середовища. Клас `Visit` з ЛР № 2 лишився навчальним прикладом для
стандарту кодування; роль документа в моделі виконує `Appointment`.
Розрахунок візиту з ЛР № 3 (`Billing`) і політики цін з ЛР № 4 (`Pricing`)
поки існують окремо.
