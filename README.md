# ClinicReception

Навчальний проєкт з дисципліни «Конструювання програмного забезпечення».
Варіант № 4: запис пацієнтів на прийом до лікаря.

Бібліотека `ClinicReception.Core` рахує вартість візиту до клініки: сума послуг
зі знижкою за курс процедур, знижки постійному пацієнтові, за обсягом, за
промокодом і за прийом у неділю, реєстраційний збір для невеликого візиту та
новий стан візиту. Звіт формується окремою чистою функцією. Консольний
застосунок рахує демонстраційний візит і друкує звіт.

## Склад рішення

- `src/ClinicReception.Core` — логіка предметної області (бібліотека класів):
  `Domain` — сутності й стани, `Billing` — розрахунок вартості та перевірки
  передумов, `Reporting` — формування й виведення звіту.
- `src/ClinicReception.App` — консольний застосунок (введення й виведення).
- `tests/ClinicReception.Tests` — модульні тести xUnit.
- `docs/lab02`, `docs/lab03` — артефакти лабораторних робіт (еталонний вивід,
  метрики до і після рефакторингу).

## Вимоги

.NET SDK 8.0 або новіший, Git.

## Складання та запуск

```bash
git clone https://github.com/influencejr/ClinicReception.git
cd ClinicReception
dotnet build
dotnet run --project src/ClinicReception.App
```

## Тести

```bash
dotnet test
```

## Стандарт кодування

Правила описано у файлі [CODING_STANDARD.md](CODING_STANDARD.md) і закріплено
в `.editorconfig`, `Directory.Build.props` та аналізаторах Roslyn і StyleCop.
Складання налаштовано в режимі «попередження як помилки». Перевірка:

```bash
dotnet format --verify-no-changes
dotnet build
```

## Відомі обмеження

Дані задаються в коді, читання з файлу ще не реалізоване. Клас `Visit` зберігає
послуги рядками й розбирає числа за культурою системи, тому його звіт залежить
від регіональних налаштувань (борг Б-2, заплановано на ЛР № 4). `Visit` і
`Appointment` поки дублюють роль документа.
