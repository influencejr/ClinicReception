# Посібник реєстратора

## Запуск

```bash
dotnet run --project src/ClinicReception.App
```

Застосунок бере дані з теки `data` поточної теки; іншу теку можна передати
аргументом: `dotnet run --project src/ClinicReception.App -- D:\clinic-data`.
Після запуску видно версію і меню:

```
ClinicReception v1.0.0

1 - Записати пацієнта
2 - Перенести запис
3 - Скасувати запис
4 - Змінити стан прийому
5 - Знайти записи
6 - Завантаження лікаря за день
7 - Додати послуги до запису
8 - Довідник лікарів
0 - Зберегти й вийти
Пункт меню:
```

На будь-яке запитання можна відповісти порожнім рядком: дія скасовується і
застосунок повертається до меню. Записи зберігаються у файл під час виходу
через пункт 0.

## Сценарії

Записати пацієнта (UC-01). Пункт 8 показує коди лікарів, далі пункт 1:

```
Пункт меню: 1
Номер пацієнта: 5
Код лікаря: DOC-THER-01
Дата (дд.мм.рррр): 24-11-2026
Помилка вводу: Дата у форматі дд.мм.рррр, наприклад 24.11.2026
Дата (дд.мм.рррр): 24.11.2026
Тривалість, хв: 20
Лист для patient005@example.com: запис № 1 на 24.11.2026 о 08:00, до сплати 450.00 грн
Записано: № 1, 24.11.2026 08:00-08:20, лікар DOC-THER-01
```

Наступний пацієнт на той самий день отримує перший вільний час після вже
зайнятого: `Записано: № 2, 24.11.2026 08:20-09:00, лікар DOC-THER-01`.

Підтвердити запис і перенести інший (UC-03, UC-02):

```
Пункт меню: 4
Номер запису: 1
Подія: 1 - підтвердити, 2 - прийом відбувся, 3 - неявка: 1
Запис № 1: стан Confirmed

Пункт меню: 2
Номер запису: 2
Нова дата (дд.мм.рррр): 25.11.2026
Перенесено: № 2, 25.11.2026 08:00-08:40, лікар DOC-THER-01
```

Додати послуги (UC-06):

```
Пункт меню: 7
Номер запису: 1
Послуга одним рядком: код кількість ціна хвилини, наприклад LAB-02 1 180,50 10
Послуга: LAB-02 1 180,50 10
Додано LAB-02, до сплати 630.50 грн
Послуга: LAB-02 два 180 10
Помилка вводу: Кількість — ціле число від 1 до 50
Послуга:
```

Завантаження лікаря за день (UC-05):

```
Пункт меню: 6
Код лікаря: DOC-THER-01
Дата (дд.мм.рррр): 24.11.2026
Завантаження лікаря DOC-THER-01 (Ткаченко Ірина Олегівна) на 24.11.2026
Робочий час 08:00-14:00, 360 хв
  08:00-08:20  № 1    Ткачук Дмитро Петрович           Confirmed
Зайнято 20 хв з 360 (5.6 %)
Вільні проміжки: 08:20-14:00
```

Знайти записи (UC-04): порожня відповідь пропускає критерій, тож лише номер
пацієнта дає всі його записи.

## Повідомлення про помилки

| Повідомлення | Що сталося | Що робити |
| --- | --- | --- |
| `Помилка вводу: ...` | відповідь не того формату | ввести ще раз за підказкою |
| `Не виконано: Пацієнта № N немає в довіднику` | номер пацієнта невідомий | перевірити номер у `data/patients.json` |
| `Не виконано: Лікаря з кодом ... немає в довіднику` | код лікаря невідомий | переглянути коди в пункті 8 |
| `Не виконано: Дата ... уже минула` | запис у минуле | обрати сьогодні або пізніше |
| `Не виконано: У лікаря ... немає вільних N хв` | день зайнятий | обрати іншу дату або коротший прийом |
| `Не виконано: Запис № N не знайдено` | номер запису невідомий | знайти запис пунктом 5 |
| `Не виконано: ... перехід ... заборонено` | подія не підходить до стану | див. таблицю станів у `docs/spec.md` |
| `Не виконано: ... неявку можна позначити лише після початку прийому` | прийом ще не почався | позначити після його початку |
| `Не вдалося прочитати чи зберегти дані в теці ...` | файли недоступні або пошкоджені | перевірити файли й права, відновити з копії |

## Дані й резервна копія

У теці `data`: `doctors.json` і `patients.json` - довідники (лише читаються),
`appointments.json` - записи (з'являється після першого виходу через пункт 0),
`logs/clinic.log` - журнал сценаріїв без імен і пошти пацієнтів. Резервна
копія - це копія всієї теки `data`, зроблена, коли застосунок не запущений.
Під час збереження застосунок спершу пише `appointments.json.tmp`, тож збій не
псує попередній файл.
